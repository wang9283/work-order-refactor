# 排班、现场作业与工作量 demo

## 启动

在项目目录执行：

```powershell
npm run demo
```

启动器先准备独立演示库与基础资料，再构建 PC/App 并启动本地服务。默认地址：

- PC：`http://127.0.0.1:3304/`
- App：`http://127.0.0.1:3304/app.html`
- 数据库：`data/product-demo/operations-demo.db`

重复启动保留排班、工单、确认和反馈。端口被占用时可先设置 `$env:PORT = '其他空闲端口'`。原有 `data/feed.db` 不作为这个启动器的演示库。

## 演示身份与生产基地

页面不再显示账号密码登录表单。打开 PC 或 App 后直接进入默认演示身份，再从页面右上角切换身份与生产基地：

| 演示身份 | 映射演示账号 | 用途 |
| --- | --- | --- |
| 总部管理员 | group.admin | 跨基地标准、组织、权限与审计 |
| 基地配置管理员 | qd.admin / dz.admin | 维护授权基地的主数据与作业配置 |
| 生产经理 | ops.manager / qd.manager | PC 月排班、工单与工作量管理 |
| 班组长 | ops.leader | App 当天调整和本组分配 |
| 员工 | ops.worker / executor.demo | 个人作业、批量确认与反馈 |
| 洗消工 | ops.wash | 车辆／厂区洗消、工作量确认与反馈 |
| 基地核算员 | qd.payroll | 核对工作量与核算状态 |

PC 默认生产经理，App 默认员工。PC 与 App 各自保存身份、生产基地和令牌：一端切换不会覆盖另一端，刷新后各端恢复上次有效选择，业务数据仍由同一数据库提供。基地下拉只显示当前身份已授权的启用基地，选择基地只会收窄数据范围。

正式账号密码认证接口为兼容既有脚本和系统保留，但不在页面上提供入口。不要在演示操作中使用或转交固定密码。

## 演示顺序

1. PC 在右上角选择“生产经理”和“工作量演示基地”，在“基础资料 → 班组与班次”核对可自定义班次：白班 `08:00–20:00`、夜班 `20:00–08:00`、常日班 `08:00–17:00`。结束时间早于或等于开始时间即跨天，夜班按结束日归属。
2. 在排班计划中核对「作业组 × 归属日期」整月表：普通料生产班、预混料生产班、装卸班、洗消班四个固定班组行；两个生产班排夜班，装卸班和洗消班排常日班，6 日与 15 日保留空白。洗消班行显示车辆／厂区洗消工单摘要；点击已安排班次查看人员、跨天归属、来源和版本，批量安排可覆盖预览。
3. App 在顶部选择“班组长”，在日程页调整当天人员，再回 PC 刷新核对；PC 保持自己的生产经理视角。临时替班需要目标作业组资格，且不改变正式班组归属。
4. 在项目终端执行 `npm run demo:events`，模拟生产和装卸上游作业。默认生产量 100 吨、装卸量 40 吨；重复执行相同日期的事件不会重复生成。
5. 在作业与工作量页查看工单人员及默认分配；生产有多个岗位，主单产量只统计一次。
6. App 在顶部选择“洗消工”，新建车辆洗消和厂区洗消：
   - 车辆洗消填写车牌号，添加 7 个固定点位演示照片，选择烘干并填写入烘起止时间，结束后计 1 辆。
   - 厂区洗消按生产区、生活区、办公区依次开始和完成，每区添加至少 3 张演示照片，三区完成后手动结束，计 3 区。
   - 无当天排班时，工单显示“待分配”和原因，不静默指定创建人。
7. 以员工账号在 App 工作量页按日期选择工单并确认；对具体工单反馈异议。
8. 以组长或生产经理处理反馈、调整人员比例，例如 100% 调整为 70%／30%。原员工确认保留，新增参与者确认自己的最新分配量。
9. 在 PC 工作量管理中核对汇总、工单详情与输出预览，再执行 `npm run demo:receive`，模拟薪酬端接收最新工作量。接收内容保存在独立演示目录的 `receipts` 中。
10. 以员工账号在 App 自建“其他现场作业”，填写作业说明，自主完单；不经过经理验收。
11. 刷新两端并切换一次身份／基地，核对各端选择正确恢复，排班、洗消过程、分配、确认和反馈仍然存在。

模拟指定日期可执行：

```powershell
npm run demo:events -- --date=2026-11-05
npm run demo:receive -- --date=2026-11-05
```

使用非默认服务端口时，终端中的 `PORT` 或 `API_BASE_URL` 应与本地服务一致。

## 验证与边界

- `npm run check:operations` 使用独立数据库和临时 API 服务验证核心闭环与权限。
- `node scripts/roster-dispatch-check.mjs` 验证默认作业组派单、资格替班、缺岗、跨天归属和历史快照。
- `node scripts/sanitation-flow-check.mjs` 验证车辆 7 点位、烘干、厂区顺序、凭证数量、越权和重复操作。
- `node scripts/isolated-acceptance.mjs` 重跑既有八套隔离回归。
- `npm run build` 进行类型检查和 PC/App 构建。
- PC/App 的排班、工单、分配、确认及反馈由本地服务持久化。
- 本轮新增的班组月表、整月示例、洗消摘要、批量覆盖预览在 Codex 内置浏览器逐项验收；实际结果见下方验收记录。
- 上游事件和薪酬接收端为本地模拟，实际阶梯计薪及真实外部协议不在本轮范围。
- 洗消使用预置演示照片，只验证字段、数量、时序和持久化；相机、相册、本地文件上传及视频尚未实现。
