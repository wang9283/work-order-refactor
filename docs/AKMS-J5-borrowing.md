# 从 AKMS 与 j5 可借鉴的能力

## 1. 结论

本原型采用“单集团、多生产基地、总部定标准、基地执行、核算主体单独确认”的设计。

从 AKMS 借鉴的是“能力与数据范围分开”的权限模型，以及标准版本、发布、冻结快照和审计留痕。没有照搬企业客户租户隔离，因为当前业务边界是一个集团内部。

从 j5 借鉴的是组织层级、作业位置、班组和班次配置，以及把交接班表转成可执行工单的路径。Excel 只作为配置草稿的输入，发布前必须人工校验。

## 2. AKMS：企业间权限架构的可借鉴部分

| AKMS 思路 | 本项目落地 | 原因 |
| --- | --- | --- |
| 角色能力 | `capability`，例如 `ticket.assign`、`payroll.close` | 控制能做什么 |
| 数据范围 | `scope`：饲料总部、发薪公司、作业基地、饲料厂 | 控制能做哪些数据 |
| 默认拒绝 | 服务端逐接口校验，前端隐藏只做体验 | 防止仅靠界面控制权限 |
| 标准与本地分离 | 总部标准只读；下属单位复制后建本地类型 | 总部保持口径统一，基地保留业务弹性 |
| 版本发布 | 表单、类型、计价均按版本保存 | 历史工单可追溯 |
| 操作留痕 | 组织、授权、模板、工单、计价和月结关键动作进入审计日志 | 关键变更可复盘 |

### 推荐继续补充

- 增加“看板只读角色”，允许跨基地聚合，但不授予明细编辑权。
- 继续细分“总部标准”“公司本地”“工单实例”的审计动作名称，并为高频操作增加专用筛选器。
- 对权限变更增加申请、审批和生效时间，避免管理员直接永久授权。
- 采用能力矩阵验收：同一能力至少测试总部、目标基地、兄弟饲料厂、执行人四类账号。

### 不应照搬

- 当前不存在多个外部客户，不需要客户空间、租户数据库分片或每客户独立管理员。
- 不应把公司层级直接等同于数据隔离。公司是发薪主体，实际作业边界落到基地、饲料厂和生产班；工区、产线仅保留兼容。

## 3. j5：组织单元与交接班配置

| j5 思路 | 本项目落地 |
| --- | --- |
| 总部、基地、饲料厂、生产班、人员 | 固定组织树，承担权限聚合、实际作业与排班 |
| 班组人员与角色 | `crew_memberships` 保存负责人、操作工、支持人员及有效期 |
| 借调 | 来源公司/基地与接收公司/基地分别记录 |
| 班次 | 班次模板记录起止时间、跨日属性和所属基地 |
| 交接班表 | 工单引用交接配置，自动带出饲料厂、班次和默认生产班 |
| 作业时间窗口 | 支持提前开始、延后结束和交接要求 |

### 推荐继续补充

- 把作业配置从类型创建抽屉拆为独立配置页，按“类型 × 饲料厂 × 班次 × 生产班”批量维护。
- 增加班次日历与节假日，把“按排班生成工单”从配置字段扩展成实际排班任务。
- 增加人员资格、排班、借调和班组四个候选条件的冲突提示。
- 交接班表增加“上班未完成事项带入下班”的显式字段，而不是只靠自由文本。

## 4. Excel 转表单

当前流程：

```text
上传 .xlsx
-> 读取第一张有数据的工作表
-> 识别表头、类型和样例值
-> 人工确认字段映射
-> 生成未发布草稿
-> 在表单版本中补充条件规则和子表
-> 发布
```

安全边界：

- 上传任务绑定上传账号及归属总部/公司。
- 下属单位不能把 Excel 草稿写到其他公司。
- 同一导入任务只能由上传人提交一次。
- 草稿不会自动成为总部标准或已发布版本。

### 推荐继续补充

- 识别合并单元格、表头分组和多行表头。
- 将重复区域识别为子表，例如逐人、逐车、逐批次明细。
- 从样例值生成单选项，并标出低频值、空值和格式冲突。
- 提供字段映射预览，用真实行数据模拟表单效果。
- 增加导入校验报告，记录原始文件哈希、解析版本和人工修改差异。

## 5. 本次明确不做的能力

- 不实现多个外部企业之间的租户隔离。
- 不让下属单位修改总部标准原件；需要变化时复制成本地资产。
- 不让 Excel 直接发布生产表单。
- 不让总部看板绕过明细权限。
- 不在首版自动判断人员月底所在公司；先由管理员按月确认并保留审计。

## 6. 验收顺序

1. 组织与授权：总部、目标基地、兄弟饲料厂、执行人四类视角。
2. 标准与本地资产：总部标准只读、本地复制、跨公司拒绝。
3. 工单执行：本基地人员、借调人员、条件必填、多人分摊。
4. 计价与月结：实际基地价格、月底发放公司、月结替换调整、关账后不可改。
5. Excel：归属越权、重复表头、草稿生成、人工发布。
6. 审计：关键动作有账号、范围、对象和前后值。
