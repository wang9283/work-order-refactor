# PC / App 免登录、角色与生产基地切换：Agent 变更计划

日期：2026-11-06。状态：T1、T2、T3 已实现，通过隔离 HTTP、构建、PC/App 真实浏览器验收及用户业务验收；相关 GitHub Issue 已关闭。改动保留在工作区，未提交、未推送、未部署。

## 1. 目标与已确认范围

- PC 和 App 均移除账号密码登录页，打开即可进入作业平台。
- 点击右上角身份区域，从下拉菜单选择演示身份；服务端按所选身份校验真实接口权限，并记录实际操作账号。
- 在身份区域左侧新增生产基地选择，切换当前端全部页面的数据视图。
- 本文件由变更计划更新为执行记录，保留原始范围、验收边界和最终证据。

已确认：两端各自保存角色与基地选择，业务数据共用；接受 T1→T2→T3 的三项顺序拆分，以及公开 HTTP＋隔离数据库、真实浏览器双端验收方案。

基地选项采用现有身份授权：只展示所选身份已有命令与数据权限覆盖的启用基地。选择基地只收窄有效范围，不模拟或扩大角色权限。

## 2. 实施前已核对的现状

1. PC 有独立登录页，App 内嵌登录页；两端共用 AuthProvider 和 localStorage 中同一个令牌。
2. PC 顶栏显示姓名和第一条角色授权，没有切换入口；导航菜单未统一按角色过滤。
3. 系统现有五种内置角色：总部权限管理员、基地配置管理员、基地工单管理员、基地核算员、执行人。生产经理演示账号使用基地工单管理员；班组长与员工同属执行人，班组长管理能力还取决于有效班组关系。
4. 生产配置等页面通过自己的状态选择基地；排班与工作量接口及 OperationsQuery 尚无基地筛选维度。
5. 服务端已有会话、能力授权和组织范围继承。客户端 can() 与服务端范围继承判断并不完全一致，不能将客户端显示当作最终权限校验。
6. 既有 Issue #1 涉及完整 demo 和排班月表，不直接用本轮需求覆盖其历史规格与验收记录。

## 3. 交互与状态方案

### 3.1 顶部入口

- PC 顺序：既有员工 App 链接 → 生产基地选择 → 角色身份下拉。角色入口显示可理解的角色名称，姓名作为辅助信息。
- App 顶部提供同样的基地与身份入口；窄屏使用短标签、弹出选择面板，完整名称在选项中显示。375px 宽度下两个入口均可操作，无横向溢出。
- 删除登录表单与退出登录按钮。初始化失败显示具体原因与重试，避免循环跳回已删除页面。
- 基地选择统一到顶栏；页面内保留日期、班组、岗位等细分筛选，删除重复且独立的基地状态。

### 3.2 演示身份

- 由服务端提供可选演示身份及其展示名称；客户端仅提交白名单身份标识，不提交可自定义的账号、角色、权限或人员身份。
- 演示身份映射至已有演示账号，复用会话、权限、班组关系与审计能力。切换本身不编辑正式账号授权或人员归属。
- 组长和员工即使共享底层角色，也要映射到不同人员账号；不能仅修改角色名称。
- 已包含：总部管理员、基地配置管理员、生产经理、班组长、员工、洗消工、基地核算员。各身份映射既有人员账号；洗消工复用执行人角色和真实洗消班组关系，核算员不因此扩展工资核算功能。
- 某身份缺少有效演示账号或必要人员关系时，给出不可用原因；补充数据采用幂等演示准备步骤，不通过数据库重置解决。
- 免登录入口受明确的演示运行配置控制，客户端与服务端状态一致；不能仅隐藏登录页或把固定密码移到浏览器。正式用户认证接口保留兼容，关闭演示配置时不提供任意身份签发能力。

### 3.3 全局上下文与切换顺序

为当前端建立单一上下文：演示身份、服务端 CurrentUser、当前生产基地、初始化／切换状态、上下文版本。角色和基地都从这一处读取。

1. 检查未保存表单；存在修改时提示继续切换会放弃修改，取消则保持原状态。正在提交写入时暂缓切换，直到请求结果确定。
2. 校验目标身份和基地的有效组合。切角色后原基地仍可访问则保留，否则选择该身份默认基地；没有可选基地时显示明确空态。
3. 建立新身份并读取匹配的权限、可选基地与初始上下文；整个过程禁止业务写入，隐藏旧业务内容。
4. 成功后一次性提交新上下文，清理旧基地班组／人员／工单选择、抽屉、分页、缓存和深链接中的失效对象。日期可保留。
5. 保留有权限的当前页面；失权页面转至该端首个可访问页面。App 保留固定四 Tab 的结构，只展示该身份可用的操作与数据。
6. 中止旧读取或按上下文版本丢弃旧响应；快速 A→B→A 切换只接受最终一次结果。
7. 切换失败保留原有效上下文并展示错误；新会话和持久化数据不得提前覆盖旧状态。失效会话只执行一次受控恢复，失败进入重试状态。

两端各记自己的身份和基地，业务数据共用；PC 的切换不修改 App 身份或基地，反之亦然。令牌存储也按端隔离，不能继续复用旧的同一键；旧共享令牌只用于明确的兼容迁移，不在每次启动时覆盖新状态。

默认采用 PC 生产经理、App 员工；刷新恢复上次有效选择，失效值回退到默认可用项；不新增“全部基地”汇总模式。首次读取应在身份和基地确定后发生，避免先显示全基地数据再收窄。

## 4. 权限与基地数据边界

### 4.1 原则

- 有效操作范围 = 所选身份已有能力与数据授权 ∩ 当前生产基地。选择基地本身不扩权。
- 菜单、路由直达、操作按钮与接口校验一致；前端隐藏入口之外，服务端继续拒绝越权请求。
- 演示请求统一携带基地上下文。列表、详情、写入、统计、导出均在服务端核对目标资源的真实归属；URL、body 中的基地／班组／工单不能绕过当前基地。
- 对组织上级、总部共享字典、共享模板等非单基地资源明确处理方式，不将共享档案复制为基地私有档案。
- 保持现有角色授权的向下继承，不向上级或兄弟基地扩大；组长范围仍为可管理班组，员工仍为本人。
- 现有脚本和非演示认证 API 保持兼容；演示入口不得因漏传基地退化为全基地查询。

### 4.2 页面覆盖表

| 范围 | 切换基地后的行为 |
| --- | --- |
| PC 排班计划 | 仅加载该基地可见班组、班次、月排班与洗消摘要；候选人员遵循原资格和替班规则 |
| PC 工单管理 | 列表、统计、详情、来源、创建及人员分配均限定基地 |
| PC 工作量管理 | 汇总、反馈、调整、输出和导出使用同一基地条件 |
| App 作业／日程／工作量 | 保留本人／可管理班组边界，同时限定基地；详情与动作接口同步限定 |
| App 我的 | 当前演示身份、所属班组与管理范围随上下文更新 |
| 生产／装卸配置 | 读取、编辑、预计单价和生成规则统一使用顶栏基地 |
| 其他工单配置 | 基地派单、预计单价和规则随基地切换；共享模板保留总部归属 |
| 组织、位置、人员、班组、班次 | 主列表限定当前基地，保留必要祖先路径；候选项不得带入另一基地旧选择 |
| 借调 | 当前基地作为借出或借入方的相关记录；对方信息仅按原授权展示 |
| 作业字典、产品物料 | 保持总部共享档案，不因基地切换改写归属；基地启用项与价格按所选基地加载 |
| 权限与数据范围 | 沿用管理授权；可见的基地相关对象收窄，角色定义仍共享 |
| 审计 | 沿用总部可查看限制；基地业务日志限定所选基地，纯总部事件明确标注为总部共享 |

实现前逐一核对表中资源的实际归属；有无法明确映射的资源时记录问题，不能用仅过滤前端表格代替服务端边界。
