# 排班、默认派单、洗消与工作量

更新：2026-11-06。本模块承接当前产品主线；`/api/tickets` 等旧工单接口继续作为兼容能力，不应用于解释本期页面和业务规则。

## 1. 业务链路

当前主链路是：

```text
基础资料与资格
  → PC 月排班
  → App 当天调整
  → 工单类型默认作业组
  → 当日有效安排与实际执行人快照
  → 工单完工
  → 人员工作量分配
  → 员工按日确认／反馈
  → 最新工作量输出
```

- 工单系统记录和输出工作量；实际阶梯计薪由薪酬系统负责。
- 生产、装卸由业务系统生成并同步完工；其他工单由员工在 App 自建、自主完结；洗消只在 App 创建并执行专用流程，PC 手工开单不提供这三类入口。
- PC 工单列表和 App 作业／工作量页共用“类型分组 → 工单类型”目录；洗消类型归入洗消分组，岗位、料类、装卸方式和车牌号继续作为业务字段筛选。
- 不设置组长或生产经理逐单验收。员工确认后仍可调整分配，无需再次确认，原确认状态保留。
- 整单工作量不随人员调整变化；同一作业项的人员贡献比例合计必须为 100%。
- 员工只能读取本人参与的工单；负责人只能管理授权作业组。

## 2. 排班与派单

### 班次

- 班次由基地维护，字段为名称、开始时间、结束时间和启停状态。
- 示例时间：白班 `08:00–20:00`、夜班 `20:00–08:00`、常日班 `08:00–17:00`。
- 结束时间早于或等于开始时间即跨天。跨天班次按结束日作为排班归属日，并展示实际开工日期。
- 排班记录保存班次名称、起止时间和跨天标志快照；后续修改班次配置不追溯历史排班或工单。

### 月排班与日排班

- 月排班和日排班共用同一套 `operations_rosters` 记录，日调整是对具体日期、班次和人员安排的修改。
- 月排班由生产经理在 PC 维护；组长或生产经理在 App 处理当天换人、加人和岗位调整。
- PC 主视图是「作业组 × 排班归属日」班组月表，固定显示可管理作业组；单元格显示班次、人数、多份安排、日调整及跨天标记，空白显示「未安排」。
- 洗消班行显示当天车辆／厂区洗消工单摘要，数据来自只读 `/api/operations/sanitation-summary`；点击跳转到工单管理详情。
- 批量保存覆盖已有安排前显示改前／改后人员差异并二次确认，每条记录携带 `revision`。历史日期和当天 `daily` 记录在 PC 只读，由 App 日程页维护。
- 历史日期在前端不可新增或批量编辑，后端也拒绝 `workDate < 今天` 的月排班写入。
- 临时替班人员必须具备目标作业组要求的资格，可以在当天参与另一作业组，但不改变其正式班组成员关系。
- 单人作业组仍按作业组建模，不为单人另建一套个人排班规则。

### 默认派单

- 同一基地、同一工单类型配置一个默认承接作业组，配置对象是业务归属，不是系统角色。
- 创建需要派单的工单时，按“工单类型默认作业组 → 作业日排班 → 资格校验”确定人员，并保存到工单快照。
- 单人默认贡献比例 100%；多人按最小比例单位均分并确定性处理余数。
- 当天无人或人员资格不符时进入待分配，并显示原因；系统不会静默使用当前登录人。
- 人员资格校验不通过时整单不保存部分合格人员，而是保留默认作业组和待分配原因，由有权限人员后续处理。
- 已有工单不因之后修改排班、班次或默认作业组而改变。工单内临时加人只影响该工单参与记录。

## 3. 车辆与厂区洗消

两类洗消都在 App 新建，执行人来自默认作业组和当天安排。

### 车辆洗消

- 必填车牌号，记录任务发布、开始、结束时间及操作人。
- 固定 7 个点位各需一张凭证：消毒液测氯试纸、洗消前/后车头左侧、洗消前/后车尾右侧、洗消前/后车顶。
- 是否烘干必选。选择烘干时必须增加入烘照片和起止时间，时间可跨天并计算分钟数。
- 凭证与烘干信息满足规则后，员工手动结束并自主完单；计 1 辆。

### 厂区洗消

- 按生产区、生活区、办公区顺序执行，前一区域未完成时不能开始后一区域。
- 每区至少保存 3 张凭证；区域开始和完成均记录操作人及时间。
- 区域补传照片不改变首次完成时间。
- 三区完成后由员工手动结束整单；计 3 区。

本期使用服务端登记的预置演示资源。客户端只能选择已登记资源，不能提交任意图片 URL；尚未接入相机、相册、本地图片上传或视频。

## 4. 工作量确认与输出

- 员工按日期查看本人已完成工单，支持多选批量确认和对单张工单反馈。
- 授权人员可处理反馈并调整参与人员或贡献比例，必须填写调整原因并携带工单 `revision`。
- 已确认人员调整后保留原确认时间，页面和输出展示最新分配量；新增参与人员需要确认自己的新分配。
- 工作量输出包含工单、作业项、人员、最新分配量、贡献比例和确认时间。
- 演示薪酬接收端只生成本地文件，不连接真实薪酬系统。

## 5. 数据与接口

### 主要数据

- `operations_assignment_rules`：基地、工单类型与默认作业组。
- `operations_crew_rules`：作业组所需资格。
- `operations_rosters`：月度/日排班及班次、归属日快照。
- `operations_sanitation`、`operations_sanitation_evidence`：洗消主记录、区域过程与凭证。
- `tickets.site_snapshot_json`：创建时冻结的班组及班次信息。
- 已有人员分配、确认、反馈和输出表继续承接工作量闭环。

### 公开接口

前缀为 `/api/operations`，更新操作使用 revision，过期返回 409。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/context` | 当前账号的班组、人员、班次、岗位、产品、装卸类型、完整工单类型目录及可自建工单类型 |
| GET/PUT | `/rosters` | 读取月排班／日排班，保存月度或当天调整 |
| GET | `/sanitation-summary` | 读取排班月表用的车辆／厂区洗消工单摘要 |
| GET/PUT | `/assignment-rules` | 读取或配置工单类型的默认作业组 |
| GET | `/roster-candidates` | 查询指定作业组、日期的可替班人员及资格结果 |
| POST/PUT | `/shifts`、`/shifts/:id` | 新建或编辑基地班次 |
| POST | `/sanitation` | 新建车辆或厂区洗消工单 |
| GET | `/demo-assets` | 读取服务端登记的演示凭证 |
| POST | `/tickets/:id/start-sanitation` | 开始洗消并记录操作时间 |
| POST | `/tickets/:id/evidence` | 添加点位凭证 |
| POST | `/tickets/:id/areas/:area/start` | 开始厂区区域 |
| POST | `/tickets/:id/areas/:area/complete` | 完成厂区区域 |
| POST | `/tickets/:id/complete-sanitation` | 结束洗消并自主完单 |
| GET | `/workloads` | 读取本人或授权范围内的工单工作量，支持类型和状态筛选 |
| GET | `/tickets/:id` | 读取工单、洗消过程、分配和确认状态 |
| POST | `/demo-sync` | 本地模拟生产、装卸上游作业 |
| PUT | `/tickets/:id/items/:itemId/assignments` | 调整人员贡献比例 |
| POST | `/confirmations` | 批量确认本人工作量 |
| GET/POST | `/feedback` | 查询或提交逐单反馈 |
| PUT | `/feedback/:id` | 处理反馈 |
| GET | `/export` | 预览最新工作量输出 |
| POST | `/self-create`、`/tickets/:id/complete` | 员工自建其他工单并自主完单 |

## 6. Demo 示例数据

- 作业组：普通料生产班、预混料生产班、装卸班、单人洗消班。
- 班次：白班 `08:00–20:00`、夜班 `20:00–08:00`、常日班 `08:00–17:00`。
- 当前示例：四个作业组补齐当前自然月，两个生产班排夜班；装卸班和洗消班排常日班；6 日和 15 日留空；不建仓储班。
- 演示账号及操作顺序见 `docs/demo.md`。

## 7. 已知限制

- 未接真实 MOM、MES、过磅或薪酬系统；生产、装卸上游事件和薪酬接收均为本地模拟。
- 未接相机、相册、本地文件上传或视频，洗消凭证只验证预置资源的选择、数量、时序和持久化。
- 未实现轮班周期、打卡考勤、工时核算、多作业组抢单或复杂派单路由。
- 当前一个基地、一个工单类型只配置一个默认作业组。
