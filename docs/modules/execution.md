# 工单执行、计件与月结

## 0. 当前产品主线（2026-11-06）

当前页面和 demo 以 `/api/operations` 的排班、默认派单、洗消、工作量确认与反馈链路为主，产品规格见 `docs/product-design.md`，模块细节见 `docs/modules/operations.md`。

- PC 日常入口是排班计划、工单管理、工作量管理；App 日常入口是作业、日程、工作量、我的。
- 生产、装卸同步完工；其他工单员工自建、自主完结，不增加经理逐单验收。
- 人员分配调整保持整单总量不变；员工确认后调整不要求再次确认，原确认状态保留。
- 工单系统负责工作量，实际阶梯计薪由薪酬系统负责。
- PC 与 App 的类型筛选共用 `/api/ticket-catalog` 的“类型分组 → 工单类型”目录：分组用于批量筛选，类型用于精确筛选；工序、料类、产品、装卸方式、实体产线、车牌号是附加业务条件。
- 生产、装卸是业务同步工单，业务字段、数量和状态只读；平台只调整人员与贡献比例并承接确认。生产工单继续采用一张主单加多条岗位明细，不因岗位扩展字段拆单。

下文第 1 节起描述既有 `/api/tickets`、计价、核算和月结能力。这些接口继续作为兼容与历史数据处理能力存在；涉及提交审核、审核后生成计件等段落不描述本期 `operations` 主线。

## 1. 业务边界

- 当前服务“饲料总部”下的直属各厂和多个生产基地，不做客户企业之间的租户隔离。
- 总部维护饲料总部标准表单、核心字段、统计和计薪口径；基地补充本地工单类型，并执行所属基地的作业。
- 看板可按全总部汇总，属于独立展示能力，不改变明细数据的访问边界。
- 人员从原基地借调到接收基地时，工单记录实际作业基地，并按接收基地当次生效的计价版本计算。
- 月底工资由人员当月在岗公司核算发放，因此实际作业基地和发放公司分别保存。
- `generic` 工单沿用发布表单和单张定价；`production` 与 `loading` 使用系统维护的业务字段、业务目录和作业明细，不进入普通表单模板编辑。
- 生产主单对应一种产品与一种料类（料类由产品物料类别带出）；同一工单的岗位明细共用整单实际产量。每个岗位内的人员贡献比例独立合计100%，工单级人员列表按人去重。
- 生产预计价按“基地＋岗位＋料类”，装卸预计价按“基地＋装卸类型”。物料类别（产线归属）影响单价，是生产价格维度；组织上的班次、产线和执行人不参与价格匹配；作业明细冻结名称、价格版本和单价。
- 物料档案维护产品主数据：产品名称决定参与的工序/岗位（参与工序标志），选定产品后生产工单的岗位明细按参与工序默认，显式指定时不得超出该范围；未显式指定时服务端按“产品参与工序（字典启用中）”补齐，不再与基地启用取交集。

## 2. 状态与版本

工单状态：

```text
pending_assignment -> pending_start -> in_progress -> completed -> closed
                   \-> cancelled       \-> pending_data / overdue
```

- 创建时冻结工单类型版本、表单版本、实际作业基地和计价版本。生产、装卸另外冻结业务类别、料类名称和逐项价格版本。
- 发布后的标准或本地版本不影响已创建工单。
- 通用工单多人分摊时，每人保存 `planned_quantity` 与 `actual_quantity`；审核时按各人实际数量求和。
- 生产、装卸的个人数量由整单实际产量乘以所在作业明细的贡献比例派生，不提供岗位数量单独修改入口；生产整单产量统计只计一次。
- 分摊之和与核定总产量的一致性在**提交审核**时就校验，不再等到审核环节才发现对不上；校验只作用于产量×单价工单，暂时不定价的工单允许先执行。
- 工单提交后即可确认执行人员本月的发放公司；提交或关闭工单中的执行人员都可确认，审核时继承该确认。
- 关闭工单后生成逐人计件记录，`workSiteId` 取实际作业基地，`payrollCompanyId` 取月底确认。

## 2.1 单张定价

每张工单单独定价，保存在 `ticket_pricing`（`ticket_id` 主键，带 `revision` 乐观锁）：

- 创建工单时若实际作业基地存在生效单价，直接写入 `status=confirmed` 的 `quantity_unit` 定价并保留 `source_price_id` 溯源；没有生效单价则写入 `status=pending`，工单照常执行，界面上标记“待定价”。
- 计价方式两种：`quantity_unit`（产量×单价，逐人按分摊产量计件）与 `lump_sum`（总包按执行人数均分）。
- 总包均分用整数分计算并保证总额守恒：先按人数取floor，余数按人员 ID 升序逐人补 1 分，因此 `100.00 元 / 3 人 = 33.34 + 33.33 + 33.33`。总包工单的计件记录 `quantity` 为空，`price_rule_version_id` 置空，不参与单价版本追溯。
- 审核前或审核后都可定价/改价；改价会删除该工单未锁定的计件记录并按新口径重算，写入 `ticket.pricing.recalculate` 审计。存在锁定、调整或后续调整记录时拒绝直接改价。
- 已关闭但仍未定价的工单不产生计件金额（`amount_micros` 为空），月结汇总以 `pendingPricing` 返回清单，存在待定价工单时**禁止关账**（返回 409），补价后自动解除。
- 单张定价覆盖类型默认价：默认价后续变更不回溯已定价工单。

## 2.2 生产与装卸作业明细

- 生产工单是一张主单、多条岗位明细；装卸工单是一张主单、一种装卸类型和一条明细。主单共用状态、提交、审核、取消和版本冲突控制。
- 基地可启用总部目录中的部分料类和装卸类型，不设启用数量上限；工序/岗位不按基地启用，适用范围由物料档案的参与工序决定。目录停用或基地取消启用只影响新单；已建工单使用冻结名称、字段和价格快照。
- 产品（物料档案）为总部级主数据，维护编码、名称、简称、规格、型号、物料类别、小包装标志与参与工序/岗位；新增和更新需 `business_catalog.manage`，带 revision 乐观锁并写审计。生产工单冻结产品名称快照，产品停用只影响新单。
- 人员在岗位明细中指派。单人贡献比例默认为100%；多人按人工填写的比例分摊。未完成岗位分配的草稿可保存，开始/提交前须完成全部岗位指派，提交时服务端再次校验各岗位合计100%。
- 补价、改价使用对应工单和基地的 `price.manage` 权限，必须提供原因并携带工单 revision；已关账或存在锁定记录时拒绝改价。薪酬明细关联 `business_work_item_id`，保留岗位、料类和个人数量来源。
- 生产/装卸不执行阶梯计薪，也不连接薪酬系统；月结继续使用工单冻结价格。
- 增量迁移 019 补充 Feed 基础字典；020 检查并补齐早期 018 库可能缺少的名称快照字段，兼容新库和旧库。已有快照不覆盖，旧通用工单不重新归类。

## 3. 候选人员

`GET /api/tickets/candidates` 返回两类人员的并集：

1. 人员行政归属在目标基地，且在作业日期存在有效班组成员关系。
2. 人员行政归属在其他基地，但作业日期处于目标基地有效借调区间。

指定班组时，借调人员必须已经加入目标班组才能被选中；未指定班组时，有效借调人员可作为通用候选。来源以 `roster` 或 `secondment` 返回，工单创建后写入人员快照。

## 4. 接口

### 工单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/tickets` | 按状态组、基地、日期、人员、类型分组/类型、来源以及生产/装卸/洗消业务字段查询；筛选后分页 |
| GET | `/api/tickets/candidates` | 查询目标基地、日期和班组下的候选人员 |
| GET | `/api/tickets/:id` | 工单详情，返回冻结表单 |
| POST | `/api/tickets` | 创建其他工单；生产、装卸和洗消不走该入口 |
| PUT | `/api/tickets/:id/assignments` | 待指派或待开始时调整执行人员 |
| POST | `/api/tickets/:id/start` | 开始执行 |
| PUT | `/api/tickets/:id/values` | 保存填报草稿 |
| POST | `/api/tickets/:id/submit` | 校验冻结表单并提交审核 |
| POST | `/api/tickets/:id/approve` | 审核通过并生成计件 |
| POST | `/api/tickets/:id/cancel` | 取消未结束工单 |
| PUT | `/api/tickets/:id/pricing` | 单张定价或改价，需 `price.manage` 与 `reason`，携带 `revision` |
| PUT | `/api/tickets/:id/business-work-items/:workItemId/assignments` | 指派岗位人员并保存贡献比例，需 `ticket.assign` |
| PUT | `/api/tickets/:id/business-work-items/:workItemId/pricing` | 兼容旧接口；生产、装卸价格由业务配置同步，平台拒绝改价 |

所有更新携带 `revision`。执行账号只能读取、开始和填写本人被指派的其他工单；具备基地指派能力的账号可管理本基地全部工单。生产、装卸工单不进入开始、填报、提交、审核或取消流程，只允许调整人员/贡献比例和确认工作量。

公开的 `POST /api/tickets` 只允许创建 `businessKind=generic` 的其他工单，并拒绝车辆/厂区洗消类型。生产、装卸由外部业务系统同步，或由内部触发规则调用同一仓储创建逻辑；洗消只在 App 创建并进入专用执行流程。生产工单指定 `materialId` 时料类取产品物料类别、岗位未显式指定时按产品参与工序补齐，显式指定时不得超出参与工序范围。系统内置生产、装卸工单类型和字段版本由服务端维护，并从普通模板/类型管理列表隐藏。

## 5. 前端页面

PC：

- `#/tickets`：查看和筛选生产、装卸、洗消及其他工单；类型条件使用两层树，按所选分组展示生产、装卸、车辆洗消等专用条件。业务工单在详情中按岗位维护人员比例与价格版本。
- `#/production-config`：基地生产适用项，仅维护物料类别；工序/岗位由物料档案的参与工序决定，不在此配置。
- `#/loading-config`：基地装卸适用项，按原料卸车/成品装车展示具体装卸方式。
- `#/business-catalogs`：独立的作业字典，维护总部统一选项；基础选项参考 Feed 项目 shared/constants.ts 与 shared/orderTypes.ts（9种物料、8个生产工序/岗位、8种装卸类型）。迁移不自动启用基地选项，不初始化价格。
- `#/materials`：物料档案，维护产品主数据与参与工序/岗位（对应原系统分类系数）；生产工单与生产触发规则选择产品后按参与工序默认本单岗位。
- `#/trigger-rules`：各类工单共用的生成规则入口，支持专用生产/装卸与通用工单类型。
- `#/tickets` 详情抽屉：展示“本单计价”和“核算金额”，可在审核前后确认本单计价（产量×单价 / 总包均分）；列表支持按计价状态（待定价、已定价）筛选。
- `#/prices`：生产、装卸、其他工单三个页签，集中维护计价版本与历史。
- `#/payroll`：列出审批前的待确认人员，按发放公司汇总，确认月底公司并执行总部月结锁定；存在待定价工单时给出“暂不能月结”提示并列出工单号。

App：

- “待办”：本人被指派的工单，按冻结表单动态渲染。
- “收入”：本人当月逐人计件与发放公司。
- 作业和工作量页提供“工单类型”筛选，选项以“类型分组 · 工单类型”展示；状态筛选与类型筛选可组合使用。
- 生产、装卸由执行人录入一次整单工作量；岗位数量从整单工作量派生，人员数量按岗位贡献比例计算。
- 通用总包工单不要求填写个人产量；通用产量×单价工单仍按人填写数量，提交时校验人员分摊与整单核定数量一致。

## 6. 审计

`GET /api/audit-logs` 当前只对总部权限管理员开放，支持按关键字、动作、对象和范围过滤。组织与授权、表单发布、工单类型发布、工单创建与流转、计价发布、发放公司确认、关账和重开均写入同一审计表；审计记录包含账号、公司或基地范围、对象及关键前后值。

## 7. 当前限制

- 工单列表没有独立的看板视图；全总部看板建议作为只读聚合服务单独实现。
- 月结调整首版以替换原计件数量并重算金额为主，新增补差的页面入口尚未开放。
- 单价版本的停用/回退当前只能通过接口数据维护，PC 的计价标准页只提供新增发布。
- PC 不提供跨人员的分摊协调面板，人员增减只在待指派/待开始阶段调整；工单进入执行后由各人分摊数量固化计价，避免审核前反复变更。
- 实际作业基地与月底发放公司已经分字段留痕，但“月底所在公司”暂由管理员按月确认，尚未接入外部人事异动数据。
- 生产、装卸工作量更正和薪酬系统同步不在本轮范围内；通用工单仍保留既有月结调整能力。
